# メモの有無

取引ごとに、その Slack 取引スレッドへ届いた投稿だけを見る。メモの有無と証憑の有無は別で、片方の結果をもう片方の代わりにしない。

この判定は `js/memo-presence.js` にあり、`tests/memo-presence.test.mjs` で固定している。公開ページは台帳に保存された `memoStatus` と `memoEvidence` を表示し、画面の側でメモあり／未確認を推測し直さない。

2026-11-07 13:59 Asia/Tokyo の1回の再走査を `data/ledger.json` に反映した。完了通知があった17件はメモあり、通知が無かった DANBALLACE ¥7,160 は未確認、返金1件は対象外（不要）である。証憑のステータスは変えていない。公開ファイルには生の Slack ログ（`raw`）とカード利用者IDを入れていない。根拠として残すのは、UPSIDER ボットの完了通知「決済メモを追加しました！」と、そのメッセージ時刻、ボットIDだけである。

完了通知が無い観測は「未確認」であり、「メモなし」とは書かない。

## メモあり

次をすべて満たす投稿がスレッドに1つでもあれば、メモありとする。

- 投稿者は UPSIDER アプリ（ボット）自身である。表示名を人間が書いただけでは当てはめない
- 取引スレッドへの通常のメッセージである
- 本文に、メモ登録を終えたことを示す「メモを追加しました」または「決済メモを追加しました！」がある

「決済メモを追加しました！」は「メモを追加しました」を含む。句点、感嘆符、前後の文、かぎ括弧が付いていても同じ完了通知とする。「メモを追加しましたか」のような問いかけは完了通知ではない。

5項目（用途、セグメント1、セグメント2、分類、内容）のメモ本文が別にあることは確認しない。完了通知があれば、本文がスレッドに見えなくてもメモありとする。

## メモなし

次は、文言が似ていてもメモありにしない。

- 人間がその文言を書いた投稿
- 人間が UPSIDER の完了通知を引用した投稿
- ボタン。ラベルが「メモを追加しました」や「準備完了」でも不可
- 「準備完了」だけの通知
- UPSIDER 以外のボットが、完了通知の文言を伝えているだけの投稿
- 5項目のメモ本文だけがある投稿。本文があっても、UPSIDER アプリ自身の完了通知が無ければメモなし
- 証憑、領収書、Drive の有無

## 証憑

証憑があるかは、会計上有効な領収書・請求書を別途見た結果である。メモの完了通知からは決めない。メモありでも証憑が無ければ、台帳上は証憑なしのままになり得る。
